## 2026-05-11

_Pushed at 22:40_

- Initialized top-level documentation scaffolding: `PROJECT.md`, `ARCHITECTURE.md`, `CURRENT.md`, `CHANGELOG.md`, `docs/modules/README.md`, `docs/adr/README.md`, `docs/adr/adr-template.md`.
- Rewrote `ARCHITECTURE.md` to lead with the four-layer model (`contracts`, `module-sdk`, `services`, `shell`) and the enforced import graph from `CLAUDE.md`; preserved the context hierarchy and module scopes.
- Initialized pnpm workspace and root tooling: `pnpm-workspace.yaml`, `.npmrc`, root `package.json` (scripts: `build`, `lint`, `typecheck`, `test`, `dev`, `ci`, `clean`), `tsconfig.base.json` (strict mode, composite), root `tsconfig.json` (project references), `.eslintrc.cjs` with `eslint-plugin-boundaries` enforcing the import graph from `CLAUDE.md`, `.eslintignore`, and `tools/ci.sh` (install → lint → typecheck → test).
- Created empty package skeletons under `packages/`: `contracts`, `module-sdk`, `shared`, `services`, `shell`, `modules/_template`. Each has `package.json`, `tsconfig.json` with project references that mirror the allowed import graph, and a placeholder `src/index.ts`. Cross-package consumption is source-mode (`main`/`types` → `./src/index.ts`).
- Populated `@emr/contracts` with the type-only public surface: branded IDs (`UserId`, `PatientId`, `ModuleId`, etc.), context shapes (`WorkspaceContext`, `LocationContext`, `UserContext`, `SessionContext`, `PatientContext`, `PatientGroup`, `TabDescriptor`), `ModuleScope`, `ContextRequirement`, `ServiceName`, `ModuleManifest` (discriminated union enforcing `requires:'patient' ⇒ scope:'patient'` at the type level), `ModuleServices`, `ModuleProps` (session/patient variants), `ModuleLifecycle`, `ModuleEvent`, and the five service interfaces (`AuditService`, `NavigationService`, `NotificationService`, `PermissionService`, `DataService`) with their supporting types. Public barrel uses `export type *`. Added `packages/contracts/CLAUDE.md`.
- Added `docs/adr/0001-module-manifest-discriminated-union.md` recording the manifest-shape decision; linked from the ADR index.
- Populated `@emr/module-sdk`: `defineModule(manifest, Component)` + `ModuleDefinition<M>`; `ModuleRuntimeContext` and `ModuleRuntime { manifest, props, emit }`; hooks `useSessionContext`, `usePatientContext` (with `PatientContextValue`), `useServices`, `useNavigation`, `useUnsavedState` (emits `unsaved-state-changed` on transitions only). Hooks throw with module-id-bearing messages when called outside a module render tree or in an illegal scope. Added `react` as a runtime dep; Vitest + jsdom + `@testing-library/react` for tests (17 tests across `defineModule.test.ts` and `hooks.test.tsx`, all green). Per-package `CLAUDE.md` and shared `test/fakes.ts` for runtime/props factories. Wired `vitest.config.ts`.
- Updated `.eslintrc.cjs` boundaries rules to allow same-element imports (intra-package) for every layer, and to use the captured `name` pattern for `module/*` so each module can import its own internals but not siblings. Behavior across layers (`contracts`, `module-sdk`, `shared`, `services`, `shell`) is otherwise unchanged.
- Added `docs/adr/0002-sdk-hooks-read-from-runtime-context.md` recording the runtime-context vs. props-based design for SDK hooks; linked from the ADR index.
- Populated `@emr/shared`: minimal FHIR R4-shaped types (`FhirResource`, `Patient`, `Practitioner`, `Encounter`, `Observation`, `HumanName`, `Reference`) and permission helpers `computeEffectivePermissions` (stub: returns `['*']`) + `permits` (wildcard-aware). Added `packages/shared/CLAUDE.md`.
- Populated `@emr/services` with stub implementations of every service interface: `AuditStore` + `createScopedAuditService` (in-memory, subscribe-able, pre-binds module/user/timestamp/id so modules cannot spoof identity), `createDataService` (returns hard-coded `samplePatients` fixtures for `Patient`, null/empty for everything else, `write` echoes, `delete` no-ops), `NavigationStore` interface + `createNavigationService` factory delegating to a shell-supplied store, `createNotificationService` console-log stub, `createPermissionService` permissive stub (`can` delegates to `permits` from `@emr/shared`; `canAccessPatient` and `canLaunchModule` return `true`). Added `packages/services/CLAUDE.md` and wired Vitest (`environment: 'node'`) with 20 tests across `audit.test.ts`, `data.test.ts`, `permission.test.ts`.
- Added `docs/adr/0003-services-delegate-to-shell-stores.md` recording the "services own their own state where possible, delegate to shell-supplied stores where not" decision; linked from the ADR index.
- Updated `.eslintrc.cjs` to honor the leading-underscore convention for unused params/vars (`@typescript-eslint/no-unused-vars` configured with `^_` ignore patterns). Matches TypeScript's existing `noUnusedParameters` behavior so stub signatures lint cleanly.
- Stood up `@emr/shell` as a Vite + React app. Added `index.html`, `vite.config.ts`, and `src/main.tsx` entry. `pnpm dev` now serves on http://localhost:5173.
- Implemented the Zustand store (`src/store.ts`) holding `session`, `tabs`, `groups`, `activeTabId`, and `activeGroupId`, with actions for `signIn`/`signOut`, `openTab`/`openTabInGroup`/`closeTab`/`focusTab`/`setTabTitle`, and `openPatientGroup`/`closePatientGroup`/`focusPatientGroup`. Tab and group IDs are monotone-counter branded strings.
- Implemented the shell-side service wiring (`src/services.ts`): owns the `auditStore` singleton plus singleton `navigationService`/`notificationService`/`permissionService`/`dataService`; exposes `createModuleServices(moduleId, userId)` for per-module bundles (with the audit service pre-scoped to that module) and `createShellAuditService(userId)` for chrome-originated events. `NavigationStore` is implemented against `useShellStore.getState()`. A lazy title-resolver hook avoids the otherwise-circular dep between services and the registry.
- Module registry and loader: `src/modules/registry.ts` validates every manifest at registration (rejects duplicate IDs, unknown scopes, unknown service names, empty id/displayName/version) and exposes `register` / `get` / `list` / `listLaunchable`. `src/modules/ModuleHost.tsx` is the only place that constructs a `ModuleRuntime`: builds session- or patient-scoped `ModuleProps` from the active session and (for patient tabs) the bound group, wires per-module services, and dispatches `ModuleEvent`s back into the store. `src/modules/registered.ts` is the canonical list of module definitions the shell loads at boot; `src/modules/welcomeModule.tsx` registers an inline `shell-welcome` session-scoped module so the loader pipeline has at least one launchable module for review.
- Chrome with clear labels on every panel: `TopBar` ("Workspace", "Location", "User" labels + Sign out), `LeftNav` ("Modules"), `TabBar` ("Open Tabs"), `PatientGroupBar` ("Patient Groups"), `AuditPanel` ("Audit Log", subscribes to `auditStore`), `HomeView` (rendered when no tab is active). Layout is CSS Grid; styles in `src/styles.css`.
- Fake login (`src/auth/Login.tsx`): single hardcoded credential pair (`admin` / `Password123`). On success, builds a synthetic `SessionContext` (Clinic workspace / MV Aurora vessel / admin user), writes it to the store, logs an `auth.signIn` audit entry, and routes to `/app` via react-router. Sign-out logs `auth.signOut` and clears the store. Per-tab URLs are not yet wired; `/app` is the chrome and routing is session-based.
- Per-package `packages/shell/CLAUDE.md` documenting hard rules (allowed imports, single `ModuleRuntime` construction site, all navigation through `NavigationService`), file layout, conventions, and what does vs. does not belong in the shell.
- Populated `packages/modules/_template` (`@emr/module-template`): `src/Component.tsx` renders a `.module-card` reading the SessionContext via `useSessionContext`; `src/index.ts` builds a `NonPatientModuleManifest` (`id: 'template'`, `scope: 'general'`, `requires: ['session']`) and exports the `ModuleDefinition` via `defineModule`. Added `react@^18.3.1` as a dependency and `@types/react` as a devDep. Per-package `CLAUDE.md` documents the single-public-entry rule, the no-props-to-component convention, and what the `pnpm new-module` script (Step 7) will rewrite when seeding a new module from this template.
- Registered the template module in the shell: `packages/shell/src/modules/registered.ts` now imports `templateModule` from `@emr/module-template` and lists it alongside `welcomeModule`. Added `@emr/module-template` as a workspace dep in `packages/shell/package.json` and a project reference in `packages/shell/tsconfig.json`.
- Loosened the boundaries rule for `shell` to allow imports from the `module` element type. The shell still only imports a module's public package entry (via package name); `registered.ts` is the only file in the shell that does this. Module-internal imports are gated by `package.json#main`/`exports` rather than by ESLint. Added a comment explaining the convention.
- Added `tools/new-module.ts` — a TypeScript generator invoked as `pnpm new-module <name> [--scope=<scope>]`. It (1) copies `packages/modules/_template` to `packages/modules/<name>/` (filtering out `dist/` and `*.tsbuildinfo` so the new tree is clean), (2) regenerates the new package's `package.json` (`name` → `@emr/module-<name>`), `src/index.ts` (manifest `id`/`displayName`/`scope`/`requires`/type-narrowed `NonPatientModuleManifest` ↔ `PatientModuleManifest`, exported as `<camelName>Module`), `src/Component.tsx` (minimal view whose only "dummy" content is the display name as an `<h2>`, with the right hook for the scope — `useSessionContext` for session/general, `usePatientContext` for patient, nothing for global), and `CLAUDE.md` (per-module stub), and (3) registers the new module in `packages/shell/src/modules/registered.ts`, `packages/shell/package.json` (sorted), and `packages/shell/tsconfig.json` references. Validates the name (lowercase kebab-case) and scope; rejects `_template` as a name and aborts if the target directory already exists. Added `tsx@^4.19.2` to root devDeps and a `new-module` root script.
- Verified the generator by creating an `@emr/module-vessel` module (general scope, `displayName: 'Vessel'`, `<h2>Vessel</h2>`). All gates pass with the generated module registered; Vite hot-resolves it through the pnpm workspace symlink on http://127.0.0.1:5209. The vessel module is kept in the workspace as the canonical generator-output example.
- Generated the three Step-8 demo modules via `pnpm new-module`:
  - **`@emr/module-hello-inbox`** (session scope) — `useSessionContext` only; renders a hardcoded inbox list with an unread-count summary line. `services: []`, `requires: ['session']`. Demonstrates the simplest scope.
  - **`@emr/module-hello-schedule`** (general scope) — `useSessionContext` + `useNavigation`; renders a hardcoded schedule for the active location and an "Open Patient Chart" button per slot that calls `NavigationService.openPatientGroup({ patient, initialTab: { moduleId: 'hello-patient-summary' } })`. `services: ['navigation']`. Patient module referenced by string ID — no cross-module import. Demonstrates the canonical general → patient transition.
  - **`@emr/module-hello-patient-summary`** (patient scope) — `useSessionContext` + `usePatientContext` + `useNavigation`; renders the bound patient's identity and group status, and a button that opens another tab in the same group via `NavigationService.openTabInGroup(group.id, { moduleId: 'hello-patient-summary' })` (self-referential for self-containment). `services: ['navigation']`, `requires: ['session', 'patient']`. Demonstrates patient-context propagation and intra-group navigation.
- Updated `packages/shell/src/chrome/LeftNav.tsx` to filter patient-scoped modules out of the launchable list — they cannot launch directly because they need an active patient group, and the canonical entry point is `NavigationService.openPatientGroup` from another module (e.g. `hello-schedule`). Replaced the previous no-op patient-scope branch in the click handler with the filter.
- Added demo list styling (`.demo-list` / `.demo-row` / `.demo-row-unread` / `.demo-row-main` / `.demo-row-meta`) to `packages/shell/src/styles.css` so the inbox and schedule rows render legibly inside the `.module-card`. These are chrome-layer utility classes that demo modules opt into; new modules with their own UI can ignore them.
